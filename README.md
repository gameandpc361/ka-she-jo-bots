# Kashejo Assistant 1.1.1 (build 7)

## v1.1.1 の変更
- 投稿JavaScriptを内部catchで保護し、失敗段階・例外メッセージ・stackを診断ログへ記録。
- ファイル選択シートを投稿画面に直接結び付け、画像UTTypeで起動。セキュリティスコープ内で読み込み。
- Webタブ/設定に現在の完全なURL表示とコピーを追加。
- 現在のWeb画面のURL・リンクDOMからアカウントIDを自動取得（API不使用）。
- 投稿間隔・キュー件数・最大画像枚数に数字入力欄を追加。スライダーも併用。
- アプリ本体Info.plistにNSSupportsLiveActivitiesを追加。

## v1.1.0 からの機能
- PhotosPickerの読込を選択変更イベントに限定し、タブ復帰時の画像二重追加を防止。
- Filesのファイル選択はセキュリティスコープとNSFileCoordinatorを使って読み込み、画像データとして検証。
- 投稿間隔を5〜3600秒に変更。
- 投稿履歴の個別削除・全削除。
- キューフォルダに親フォルダIDを追加し、階層パス表示・サブフォルダ作成・配下を含む削除に対応。
- 下書きのチェック選択、全選択/全解除、選択削除、フォルダ移動。
- `{random}` は8文字、`{random:数字}` は指定長（1〜128文字）に展開。
- Moreタブにアカウント管理、バージョン、ビルド番号、GitHubリンク。
- アカウントごとにWKWebsiteDataStoreの永続領域を分離。設定共有・下書き/履歴/フォルダ共有は個別に選択可能。
- アプリ用1024pxアイコンを追加。

## アカウントの扱い
- アカウントを切り替えると、専用のWebKit保存領域を使用します。ログインCookieはアカウント間で共有しません。
- 「既定アカウントの設定を共有」を有効にすると、URL/ID/キュー間隔/件数/画像枚数/履歴の開き方を既定アカウントの設定に同期します。
- 「下書き・履歴・フォルダを共有」を有効にすると、同じローカルデータストアを使用します。
- アカウント削除では専用WebKit領域のデータ消去を要求します。OSの非同期処理により、削除完了まで時間がかかる場合があります。

## 投稿と画像
- 投稿はアプリ内WKWebViewに表示されたKashejoの通常フォームを使います。API投稿へ切り替えることはありません。
- GIF/PNG/JPEG等の画像バイト列を保持して送信します。ファイル拡張子ではなく画像データを判定します。
- 10MiB超過はアプリで警告するだけで、選択や送信をブロックしません。最終的な受け入れはKashejo側の制限に従います。

## キュー・バックグラウンド
- キュー間隔は5〜3600秒。1回の上限は設定可能（最大50件）。
- iOSはバックグラウンドでWebKitを確実に実行しません。BGTaskScheduler/Live Activityも投稿の継続を保証しません。連続投稿中はアプリを前面に置いてください。

## ログ
- 画面遷移、ナビゲーションHTTP応答、フォーム送信のメソッド/パス/HTTPコード/時間/応答プレビュー等を記録します。
- Cookie、CSRF、Authorization、パスワード等は記録しないかマスクします。
- WKWebViewの全サブリソース通信を完全なパケットダンプとして記録する機能ではありません。

## ビルド（iPhoneのみ）
1. ZIPを展開し、内容をGitHubリポジトリのルートへ配置して既存ファイルを置き換えます。
2. ZIP内は `github/workflows/build-ipa.yml` です。GitHub上では `github` フォルダ名を `.github` に変更し、`.github/workflows/build-ipa.yml` にしてください。
3. GitHub Actionsで `Build unsigned iOS IPA` を実行し、Artifactをダウンロードします。
4. SideInstaller等で署名してインストールします。

## 検証上の注意
このソースZIPはSwift構文・設定・ZIP構造を検査していますが、この実行環境にXcode/iOS SDKがないため、XcodeビルドおよびiPhone実機テストは未実施です。GitHub Actionsのビルド結果を確認してください。
