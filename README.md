# Kashejo Assistant — Webフォーム版 / Live Activity対応

## 今回の実装
- `/api/v1/me` と `/api/v1/posts` を認証・投稿に使用しない構成へ変更。
- アプリ内WKWebViewで通常ログインし、WebKitの同一セッション内から現在表示中のHTML投稿フォームを検出。
- `csrf` と `body` を持つ実フォームの `action` / `method` を利用し、フォームの既存項目を保持したまま `multipart/form-data` を送信。
- 画像は `images` フィールドに複数添付。フォームが見つからない場合は投稿を中止し、APIや別URLへフォールバックしない。
- フォーム送信先は同一オリジンのみ許可。Cookie/CSRFをログに出力しない。
- ログイン判定はWeb画面のログインフォーム/ログアウト・プロフィール導線による保守的な判定。判定材料がなければ「判定不能」とする。
- 投稿履歴、下書き、連続投稿キュー、予約時刻通知。
- ActivityKit Live Activity / Dynamic Islandでキュー進捗・状態・次回処理予定を表示。
- BGTaskSchedulerの予約は追加。ただしOSが実行を保証しないため、バックグラウンド中のWebKit投稿は実行しない。

## 重要な制限
1. KashejoのWebフォームが現在のWebViewページに存在する状態で投稿してください。ホーム画面などフォームのないページでは安全のため停止します。
2. 実際のHTMLフォームの構造・投稿後URLが、以前提供された通信ログと異なる場合は成功判定できません。初回は本文のみのテスト投稿を推奨します。
3. `scheduled_at` はフォームに項目がある場合に限り既存値を保持しますが、サーバー側が予約投稿を処理することは未確認です。このアプリの予約は、アプリが実行可能なときに処理を試みる補助機能です。
4. iOSはBGTaskSchedulerの実行時刻を保証しません。Live Activityもバックグラウンド実行を延長しません。アプリが停止/終了中の確実な自動投稿は実現できません。
5. ログイン判定はサイトのDOM表示に依存します。UI変更後は「判定不能」になる場合があります。
6. このZIPはソース一式です。Xcode 16.4 / iOS SDK 18.5での完全ビルド・実機テストはこの環境では実施していません。

## iPhoneだけでIPA化
1. ZIPを展開し、内容をGitHubリポジトリのルートへ配置。
2. `github` フォルダを `.github` に変更して `.github/workflows/build-ipa.yml` にする。
3. GitHub Actionsから `Build unsigned iOS IPA` を実行。
4. Artifactをダウンロードし、SideInstaller等で署名してインストール。

## 初回テスト
1. アプリのWebタブでKashejoへログイン。
2. サイト内の通常の投稿画面を開き、本文入力欄が表示された状態にする。
3. アプリの投稿タブに戻り、まず本文だけでテスト。
4. 成功後、画像1枚、複数画像の順に確認。
5. 失敗時はログのHTTPコード/stageを確認。Cookie、CSRF、パスワード等を含むログは共有しないでください。
