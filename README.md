# Kashejo Assistant 1.1.3 (build 9)

## v1.1.3 の変更
- 写真アプリとファイルアプリの選択ボタンを縦並びの独立した大きなボタンに分離。タップ領域が重ならないように変更。
- 写真Pickerの選択可能枚数を、すでに追加済みの画像数を差し引いた残り枚数に合わせる。

## v1.1.2 の変更
- Filesの画像選択をSwiftUI fileImporterからUIDocumentPickerViewControllerへ変更。Filesの場所（このiPhone内、iCloud Drive、接続済みファイルプロバイダ等）から画像を選べるようにし、複数選択・セキュリティスコープ・NSFileCoordinatorで読み込み。
- 下書き・キュー画面を「フォルダ階層 → 連続投稿キュー → 下書き一覧」の順に再構成。
- 下書き表示をリスト／プレビューカードで切り替え、選択状態・一括削除・フォルダ移動・個別投稿を維持。
- キューの実行ログを最大500件保存し、専用画面で確認可能に。次の投稿までの残り時間を1秒単位で表示。
- User-Agentの現在値確認、カスタム設定、標準値へ戻す操作を追加。設定はアプリ内に保存し、WebViewへ適用。
- Moreにシステム情報ページを追加。ページ表示中のみ約2秒ごとに更新し、離れると計測タスクを停止。
- アプリ領域の概算容量、端末容量・空き、物理メモリ、システム空きメモリ推定、アプリのメモリ使用量、アプリCPU使用率、機種・iOS・アプリ情報を表示。

## システム情報の制約
- iOSの公開APIではシステム全体のCPU使用率を一般アプリから正確に取得できないため「取得不可」と表示。アプリ自身のCPU使用率を計測する。
- 空きメモリはMach VM統計のfree + inactiveページを使った推定値。iOSのメモリ圧縮やキャッシュのため厳密な「利用可能メモリ」とは異なる。
- アプリ容量はアプリのサンドボックス内ファイルを合計した概算で、設定アプリに表示される厳密なインストールサイズとは異なる。
- システム情報は画面表示中のみ更新する。

## Files画像選択について
投稿画面の「ファイル」はiOS標準の書類ピッカーを開く。左上の「ブラウズ」から「このiPhone内」「iCloud Drive」や利用可能なファイルプロバイダを選択し、画像を選ぶ。画像UTTypeとして公開されているファイルが対象。iCloud上で未ダウンロードのファイルやプロバイダ側の一時的なエラーは読み込みに失敗する場合がある。

## 既存機能と互換性
- 投稿はアプリ内WKWebViewに表示されたKashejoの通常フォームを使用し、API投稿には切り替えない。
- 既存の下書き・履歴・フォルダの保存形式は変更していない。
- GIF/PNG/JPEG等は元の画像データを保持して送信する。
- キューはアプリ前面での動作を前提とする。iOSはバックグラウンドでWebKitフォーム送信を保証しない。Live Activityも投稿処理を継続させる機能ではない。
- JITやメディア変換は今回追加していない。

## ビルド（iPhoneのみで操作）
1. ZIPを展開し、内容をGitHubリポジトリのルートへ配置して既存ファイルを置き換える。
2. ZIP内に `.github/workflows/build-ipa.yml` を含む。
3. GitHub Actionsで `Build unsigned iOS IPA` を実行し、Artifactをダウンロードする。
4. SideInstaller等で署名してインストールする。

## 検証上の注意
このソースZIPはSwift構文解析、YAML/Plist、ZIP構造を検査したもの。実行環境にXcode/iOS SDKがないため、Xcodeによる実ビルドおよびiPhone実機テストは未実施。GitHub Actionsでビルドし、実機でFilesピッカー・投稿・キュー・User-Agent・システム情報を確認すること。
