# Kashejo Assistant — 診断機能付き iOS 試作版

Kashejo向けのiPhone用投稿補助アプリです。KashejoのAPI/Web仕様に依存するため、実機でのログイン・投稿確認が必要です。

## 今回の修正
- WebViewを独立した「Web」タブに表示。トップページボタンが非表示のWKWebViewだけを読み込む問題を修正。
- `/a/{accountID}/posts` はGETで404になる環境があるため、投稿画面ボタンから固定URLへ遷移しない設計に変更。トップページを開き、Kashejoサイト内の実際の導線を使う。
- ログイン状態を `GET /api/v1/me` で確認。HTTP 200だけでログイン済みと誤判定せず、ユーザー情報の有無も確認。
- `evaluateJavaScript` に非同期Promiseを返していた問題を修正。`WKWebView.callAsyncJavaScript` で非同期処理を待ち、Swiftへ辞書形式で返す。
- 診断ログを追加。ログイン確認、投稿開始/応答/失敗、ローカル保存失敗などを記録。最大300件を保持し、コピー可能。
- 投稿結果にHTTPステータスと処理段階を記録。
- 未ログイン時は投稿処理を止め、Webタブでログインするよう案内。
- 画像投稿フォームが見つからない場合、画像を黙って捨てて本文だけ投稿することを防止し、明確なエラーを表示。

## 機能
- アプリ内WebViewでKashejoを開いてログイン
- ログイン状態確認
- テキスト投稿（`POST /api/v1/posts` JSON）
- 投稿フォームがWebView上に存在する場合の画像投稿試行（multipart）
- 複数画像選択、下書き、投稿履歴、連続投稿キュー
- 予約時刻の通知と、アプリが前面にある間の予約投稿チェック
- サイトURL、アカウントID、連投間隔、最大件数、画像枚数の設定
- 診断ログの表示・コピー・消去

## 重要な制限
- `GET /api/v1/me` の実際のログイン応答形式が想定と異なる場合、ログイン状態が「確認不能」になります。その場合は「ログ」タブのログを確認してください。
- テキスト投稿APIは過去の利用者確認情報に基づきますが、この改良版での実機投稿は未検証です。
- 画像投稿のAPI仕様は確定していません。WebView内に `csrf` と `body` を持つ実際の投稿フォームが見つかった場合のみ送信を試します。フォームがなければ投稿を中止します。
- 投稿画面のGET URLが404になる問題を避けるため、アプリ側で存在未確認の投稿URLを組み立てません。
- 予約投稿はアプリが前面で動作している間のみ実行チェックします。アプリ終了中の自動投稿は保証できません。
- このプロジェクトは未署名IPAを生成します。SideInstaller等で署名してインストールしてください。

## iPhoneだけでビルド
1. ZIPを展開してGitHubリポジトリへアップロード。
2. `github` フォルダを `.github` に変更し、`.github/workflows/build-ipa.yml` に配置。
3. GitHub Actionsで `Build unsigned iOS IPA` を実行。
4. Artifactをダウンロードし、iPhoneのサイドロード環境で署名・インストール。

## 最初の確認手順
1. アプリの「Web」タブでKashejoトップページを開く。
2. WebView内でログインする。
3. 「ログ」タブの「ログイン状態を再確認」を押す。
4. ログイン済みと確認できてから、本文だけのテスト投稿を行う。
5. 画像投稿は、Webタブで実際の投稿フォームを表示できることを確認してから試す。
6. 失敗時は「ログ」タブでログをコピーし、共有する前にCookie・認証情報・個人情報が含まれていないか確認する。

## セキュリティ
- APIキーをソースコードへ埋め込んでいません。
- Cookieや認証ヘッダーの値はログへ出力しません。
- ログにはアクセス先URLのパス、HTTPステータス、エラー文が含まれます。外部へ共有する前に個人情報が含まれていないか確認してください。
